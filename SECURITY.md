# Security Policy

If you find a security vulnerability, please do not open a public issue.

## How to report

- Contact the maintainers privately rather than through the issue tracker.
- Include enough detail to reproduce the problem: the package name and version or
  the Studio version, the target framework you were building for, and the steps
  that trigger it.
- If you know the impact, or a way to reduce the risk in the meantime, say so.

You will get an acknowledgement, and an estimate of when a fixed version will be
published, before any public disclosure.

## Scope

This policy covers what is distributed here:

- the published NuGet packages
- the BluePrint Studio binaries attached to a release
- the sample projects in `Demo/`

A vulnerability in the library is handled by the maintainers and reaches you as a
new package version. Report it the same way; it will be routed to the right
place.

## Supported versions

Fixes are published against the latest released version. A published package
version is never replaced, so a security fix always arrives as a new version
number.
